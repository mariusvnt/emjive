# Data

One file, `data/products.json`, fetched client-side (no backend, no server-side templating). Hand-formatted with aligned columns — see the "how it's written" note at the end before running any formatter over it.

## Top-level schema

| Field | Type | Purpose |
|---|---|---|
| `categories` | `string[]` | Source of truth for valid `product.category` values. The header's dropdown menu (`.ring`/`.neck`/`.wrist`) is a separate, hand-written list in the HTML — keep the two in sync by hand (see `pages.md`). |
| `metals` | `string[]` | Source of truth for valid metal keys, used throughout `icons`, `metalDetails`, `assets.top-shot`, and `product.metal`. Must stay in sync with `METAL_PRESETS` in `js/three-viewer.js` (see `client-scripts.md`). |
| `sizesByCategory` | `{ [category]: string[] }` | Standard size options offered in the "Choose a size" popup — keyed by *category*, not per-product. Empty array = no standard sizes for that category. |
| `sizeUnits` | `{ [category]: string }` | Unit label next to the popup's custom-size field, per category (e.g. `"mm"` for ring). If both this and `sizesByCategory` are empty for a category, the product page's "Select" button disables itself. |
| `products` | `Product[]` | The catalog. Currently 3 entries (Furcula, Foramen, Disc), all category `"ring"`. |

## Product object schema

- **`id`** (`string`) — e.g. `"01"`. Used in `product.html?id=...` URLs, and as the anchor `scripts/auto-render.js` scopes its text-patching to (see `tooling.md`).
- **`name`** (`string`) — display name; also the basis for auto-render's generated filenames (lowercased, spaces→hyphens).
- **`category`** (`string`) — one of `categories`; looks up `sizesByCategory`/`sizeUnits`.
- **`description`** (`string`) — shown on the product detail page only. Empty string falls back to "No description yet." in `js/product.js`.
- **`icons`** (`{ [metal]: string }`) — one 512×512 transparent WebP path per metal, every metal (not just the default) — the metal picker swaps this live. Used as the 3D viewer's `.emjive-3d-viewer__poster` overlay (shown until the model's first frame renders), the homepage card's fallback when `model` is empty, and the carousel's fallback slide.
- **`photos`** (`string[]`) — extra photography slides appended to the carousel after the model/icon slide. Empty array hides the carousel's nav entirely if it leaves only one slide.
- **`assets.xray`** (`string`) — single path, carousel backdrop image. Empty string hides it.
- **`assets.top-shot`** (`{ [metal]: string }`) — one 1024×1024 WebP per metal, straight-down camera, lit without the studio HDRI, with an invisible "finger" occluder plane baked into the render so the ring's own hidden-from-above geometry (the far side of a gap in the shank, the inner wall of the hole) doesn't show through once composited over a hand (see `tooling.md`'s `scripts/auto-render.js` section). Generated by `scripts/auto-render.js`, populated for all 3 current products. Read by `js/main.js`'s `updateHeroRings()` — see `onHand` below.
- **`onHand`** (`{ visible: boolean, x: number, y: number, scale: number, rotation: number }`) — controls whether and how this product's `assets.top-shot[metal]` image is overlaid on the homepage hero's x-ray hand. `visible` gates whether `updateHeroRings()` creates a `.reveal__ring` `<img>` for this product at all — any number of products can have this `true` at once, each getting its own independently-positioned image. `x`/`y` are that image's center as a % of the hand image's own width/height (not the viewport); `scale` is its width as a % of the hand image's width; `rotation` is in degrees. All four are set inline per-image from this data (`css/style.css`'s `--ring-x`/`--ring-y`/`--ring-size`/`--ring-rotation` are only the pre-JS fallback values). See `pages.md`/`styling.md` for the reveal/positioning mechanics these feed into.
- **`model`** (`string`) — `.glb`/`.gltf` path. Empty string → falls back to `icons[metal]` instead of a 3D viewer.
- **`cameraOrbit`** (`string`, `"<theta>deg <phi>deg <radius%>"`) — default/reset camera framing, parsed by `js/three-viewer.js`'s `parseOrbitString()` (see `client-scripts.md`). Also inherited (radius only, theta forced to 0) by auto-render's top-shot renderer.
- **`metal`** (`string`) — singular. Picks which of `icons`/`metalDetails` the *homepage* card defaults to (no picker there), and which metal's `assets.top-shot`/`assets.xray` gets used wherever a single, unpicked variant is needed (the hero ring overlay, the product carousel backdrop). The product page separately defaults its own picker to this value but lets the visitor change it.
- **`metalDetails`** (`{ [metal]: { price: number, weight: string, composition: string } }`) — per-metal specs, shown in the product page's Characteristics section, re-rendered on every metal-picker switch. `price: 0` renders as "Price on request".

## Current data gaps (so placeholder content doesn't get mistaken for a bug)

Verified directly against the file: Foramen and Disc have no `photos`, no `assets.xray`, empty `description`, and `price: 0` for every metal. Every product's `weight`/`composition` is empty for every metal, including Furcula's. Furcula itself has real prices for all three metals (220/350/240) and a real description/photos/xray — it's the one fleshed-out example the other two haven't caught up to yet.

## How it's written

By hand for most fields, or patched by `scripts/auto-render.js` for `icons`/`assets.top-shot` specifically — via regex text-surgery on the raw file text, not `JSON.stringify` (see `tooling.md` for why: it preserves this file's hand-aligned column formatting, which a full re-serialize would flatten). **Don't run a formatter/prettify pass on this file** — it'll survive structurally but lose that alignment.
